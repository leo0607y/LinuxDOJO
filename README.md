# 🐧 LinuxDOJO / LinuxQuest — はじめの一文字から学ぶ Linux 教材

Linux を初めて使う人が、**説明を読む → 1つ入力する → 結果を確かめる** の順で学べる対話型教材です。
ターミナルや `sudo` の意味を知らなくても、はじめてモードから始められます。

- **はじめてモード（24レッスン）**：文字の入力、Enter、スペース、現在地、ファイル、`sudo`、インストールを1操作ずつ学ぶ
- **基礎練習モード（66レッスン）**：ファイル操作・検索・権限・調べ方・SSH接続とファイル転送・vim（インストールから）を説明付きで反復する
- **応用練習モード（46レッスン・7ユニット）**：ワイルドカード、パイプでの集計（`sort` `uniq -c` `cut`）、`grep` の正規表現、環境変数、プロセスの調査と停止、容量の調査、vim での置換（`:%s`）を学ぶ
- **達人モード（246レッスン・8ユニット）**：検索とバックアップ・復元、ネットワークとHTTP、ユーザーと権限、awk・sed、Git、スクリプト作成、サービスとログを練習する
- **正解は1つではない**：同じ目的に届く書き方（`mkdir -p practice`、`chmod +x`、`:x` など）も正解にする。成功すると、ほかの書き方も紹介する
- **実践モード**：**102ミッション**（Linux・運用・Extraの既存59問 ＋ セキュリティ実践19問 ＋ 復旧・性能・ネットワーク運用24問）。調査、修正、再検証、証拠保全と報告まで学ぶ
- **課題まつり（総合復習・228課題）**：目的だけを読んで手順を自分で組み立てる、状態判定型の課題。基本8題と12パック220題。短いドリル、実務シナリオ、バックアップと復元、ネットワーク運用、ユーザー管理とGit、自動化の準備まで、★1〜★3の難しさで復習する
- **Linux 自由自在マップ**：分野ごとの達成度と全体の「自由自在度」を表示。全分野100%に加え、総合課題をすべて手本なしで解くと「Linux 自由自在マスター」
- モードごとに進み具合を保存し、選んだモードの「続きから」再開できる
- 毎日3課題を目標に、学習XPと連続学習日数を表示。はじめて・基礎練習・応用練習・達人・実践の成功で10 XPを獲得（同じ課題は1日1回、翌日以降の復習も対象）
- 本体は Python 3 標準ライブラリと bash。実践モードには3段階ヒント・模範解答・ランク・称号もある
- Docker がなくても、実践モードの Docker 課題はシミュレーションで学べる

### 初めての人へ：まず、この言葉だけ

**Linux（リナックス）** は、パソコンやサーバーを動かす基本ソフト（OS）の一つです。
**ターミナル** は、文字でコンピューターに指示するための画面です。そこへ入力する指示を **コマンド** と呼びます。

例えば、`echo こんにちは` と入力して **Enterキー**を押すと、「こんにちは」と表示されます。
`echo` と `こんにちは` の間には半角スペースを1つ入れます。
画面に最初からある `$` や `>` は「ここから入力できます」という目印（プロンプト）で、入力する文字には含めません。
間違えたらBackspaceで消して入力し直せます。全部覚えてから始める必要はありません。

**インストール** は、使いたいソフトを追加することです。Ubuntu系のLinuxでは `apt` というコマンドで管理します。
**`sudo`** は、管理者の権限でそのコマンドを実行するために付けます。意味を確認してから使うものです。
はじめて・基礎練習モードでは模擬環境で試すので、教材内の `sudo` や `apt` が実際のパソコンの設定やソフトを変更することはありません。

## 🚀 起動方法

### Gitコマンドを使わずに始める（Ubuntu）

1. ブラウザーで[この教材のGitHubページ](https://github.com/leo0607y/LinuxDOJO)を開き、**Code → Download ZIP** を選びます。
2. ダウンロードしたZIPファイルを、ファイル管理アプリで展開します。
3. 展開したフォルダの中の、`start.sh` と `README.md` がある場所を開きます。
4. フォルダの空いている場所を右クリックして、**「端末で開く」**を選びます。
5. 初回だけ、開いたターミナルに次の1行を入力してEnterキーを押します。

```bash
bash install-start.sh
```

これは、自分専用の `start` コマンドを登録する操作です。`sudo` は不要です。
`bash` は起動手順ファイルを読むプログラムで、後ろの `install-start.sh` が今回読むファイル名です。間には半角スペースを入れます。
登録できたら、次回からは教材のフォルダを開かなくても、ターミナルで次の1語を入力するだけです。

```bash
start
```

登録先は `~/.local/bin/start` です。`~` は自分のホームフォルダを表します。
その場所がコマンドの検索先（`PATH`）に入っていない場合、登録時に表示される次の1行を実行してから `start` を入力します。

```bash
export PATH="$HOME/.local/bin:$PATH"
```

シェルの設定ファイルは自動で書き換えません。次のターミナルでも `start` が見つからなければ、同じ1行を実行してください。
別の `start` コマンドがある場合は上書きせず中止します。その場合や、登録せずに試す場合は `bash start.sh` で起動できます。
以前から `start` という別名（alias）や関数を設定している場合は、`type start` でどれが選ばれるか確認してください。
ZIPから取得した場合も、`bash` を使う方法なら起動ファイルの実行権限を自分で変更する必要はありません。

登録後も教材のフォルダは残してください。移動する場合は移動前に `bash install-start.sh --uninstall` で登録を解除し、移動後のフォルダで登録し直します。
登録解除は起動コマンドだけを取り除き、教材や学習の進捗は残します。
Pythonがないと表示された場合は、ランチャーに出る案内に従ってください。教材が自動で `sudo` を使ってインストールすることはありません。

Linux（Ubuntu系など）のターミナルで使います。Windows では次の「Windows で使う」を見てください。

### Windows で使う

教材フォルダの **`start.bat` をダブルクリック**すると起動します。

| Windows の環境 | 使えるモード |
|---|---|
| WSL（Ubuntu など）に python3 が入っている | 全モード。自動で WSL 版が起動します |
| WSL がなく、Windows に Python 3.8 以上がある | はじめて・基礎練習・応用練習・達人・総合復習（模擬ターミナルなので Linux は不要） |

- Python は https://www.python.org/downloads/ から入れます。インストール画面で「Add python.exe to PATH」にチェックを入れてください。
- 実践モードは本物の bash と Linux コマンドを使うため、WSL が必要です。PowerShell を管理者として開き、`wsl --install` を実行して再起動します。そのあと Ubuntu で `sudo apt install python3` を実行してください。
- 進み具合（`save_data.json`）は Windows 版と WSL 版で共通です。WSL から Windows 側のフォルダ（`/mnt/c/...`）で起動した場合、実践用の作業場所は Linux の権限が正しく働く WSL 側（`~/.local/share/linuxdojo/workspace`）に作られます。
- WSL があっても Windows 版で起動したいときは、コマンドプロンプトで `start.bat --windows` を実行します。
- Windows 版の模擬ターミナルでは、`chmod` の権限を教材の中で記録して再現します。実際のファイルの権限は変更しません。

タイトル画面でEnterを押すとメニューが開きます。**初めての人は「はじめてモード」から**始めてください。
新しいセーブでは、はじめてモードが最初の入口になります。既存の実践モードのクリア実績は保持されます。

モードを切り替えても、ほかのモードの進捗は消えません。今日は基礎練習、明日は実践、という使い方もできます。
初学者モードを最後まで終えたら、`[1]` でモード選択へ進み、`[2]` から好きなレッスンを復習できます。

### 自力で操作できるようになるための進め方

はじめてモードは最初の5課題だけ入力するコマンドを表示します。その後は、説明と目的を読んで自分で入力します。
分からなければ `hint` を1回ずつ使い、考え方、道具、入力例の順に確認できます。`answer` で直接入力例を見ることもできます。
ヒントを見た課題は、あとで何も見ずにやり直してみてください。

達人モードでは、ファイルを作っただけでなく中身や権限、アーカイブの内容、サービスの稼働状態なども判定します。
総合課題では、必要な対象を守ること、変更前の退避、作業後の確認、手順の順番も扱います。
自由自在マップは全レッスン・全総合課題・全実践ミッションを含み、総合課題の手本なし達成数も表示します。
ヒント付きの達成は学習履歴として残りますが、マスター称号には総合課題をすべて手本なしで解き直す必要があります。

スクリプト作成の模擬課題は、指定されたソースと保存内容を確認する練習です。模擬環境ではスクリプトを実行しません。
自由な実装や実行時の動きは、本物のBashを使う実践Stage 6で確認します。実践モードでも管理コマンドやDockerは設定により模擬動作になります。

修了の目安は、初めて見る目的に対して「対象と現状を確認する → 必要な操作を調べる → 退避して変更する → 結果を確かめる → 失敗時に戻す」を説明しながら実行できることです。
サーバーごとの構成やディストリビューションの違いまで一律に保証する教材ではありません。まず日常の操作と基本運用を自力で進める力を身につけます。

### SSHも「接続するところ」から練習する

基礎練習では、`ssh ユーザー名@接続先` の読み方、接続先の指紋（フィンガープリント）の照合、接続を拒否する判断、確認後の接続を学びます。
接続後は `hostname` や `pwd` で「今どのコンピューターにいるか」を確かめ、`exit` で元に戻ります。
ポート番号・秘密鍵の指定、`scp` による送信と受信、接続に失敗したときの表示も練習します。
これは外部へ通信しない模擬接続です。実際の秘密鍵やパスワードを入力する必要はありません。
実践Stage 4では、SSH設定ファイルと権限、`rsync` の同期を本物のコマンドで確かめます。

### vim は「入っていない」ところから練習する

基礎練習の最後では、`vim memo.txt` が `Command 'vim' not found` になる場面から始めます。
`sudo apt update` → `apt show vim` → `sudo apt install vim` → `vim --version`（または `which vim`）で確認、と自分で入れてから使います。
そのあと、入力モード（`i`）で好きな文を書く → `Esc` で戻る → `:wq` で保存、変更を捨てる `:q!`、行の削除 `dd`、取り消し `u`、検索 `/文字`、上書き保存 `:w` を練習します。
模擬 vim では1回の Enter を1つの操作として扱います。Esc キーの代わりに `esc` と入力しても同じです（Windows のコンソールでも練習できるように）。
実践ミッション 6-6 では、本物の vim で設定ファイルを直します。

### 課題まつりで、手本を見ずに使えるか確かめる

メニューの `[8]` では、目的と達成条件を読んで、自分で複数のコマンドを選びます。
課題はテーマ別のパック（ファイル整理・ログ解析・設定と vim・システム管理・リモートと障害対応など）に分かれ、★1（基本）〜★3（総合）の難しさが付いています。
判定は「最後の状態」（ファイルの中身・権限・プロセス・環境変数・入っているソフト・サーバー側のファイルなど）を見るので、やり方は自由です。必要な課題では、確認コマンドの実行や手順の順番も判定します。順番を間違えた（退避する前に書き換えた、関係ないプロセスまで止めた など）場合は不合格になります。
`check` は入力した文字列の暗記ではなく、実際の練習用ファイルの中身や状態を判定します。
分からなくなれば `hint` や `answer` を使えます。答えを見たかどうかも記録されるので、後で見ずに解き直す目安になります。

### 実践モード

ミッションを選ぶと、**専用のサブシェル（本物のbash）** が起動します。

```
 LQ 2-7  workspace/stage_02 $ awk '$9 == 500 {print $1}' access.log | sort | uniq -c | sort -rn > report.txt
  ✨ 達成条件を満たしたようです！ check と入力して判定しましょう。
 LQ 2-7  workspace/stage_02 $ check
```

タブ補完・パイプ・リダイレクト・`Ctrl+R` 履歴検索・`Ctrl+Z`/`bg`/`fg` のジョブ制御など、普段の bash の機能がそのまま使えます。

### 実践モードのゲーム内コマンド（サブシェル内で使えます）

| コマンド | 説明 |
|---|---|
| `mission` | 問題文・達成条件・作業ディレクトリを再表示 |

## 🔐 セキュリティの仕事につながる実践の進め方

実践Stage 8〜10は、許可された範囲で**観察 → 根拠を保存 → 問題を説明 → 修正 → 正常系と拒否されるべき操作を再確認 → 報告**する力を練習します。
単に応答が変わった、ファイルができた、というだけではなく、対象と証拠の整合性、残すべき正常動作、修正内容を確認します。

| 段階 | できるようになること | 自分で説明する確認点 |
|---|---|---|
| Linux基盤 | ファイル・権限・通信・ログ・自動化を扱う | どの対象に、なぜそのコマンドを使うか |
| 対象範囲 | 許可された資産、禁止する操作、連絡先を明確にする | 何を調べてよく、どこで作業を止めるか |
| Web検証 | 認証と認可、応答設定、Cookie属性を比較する | 自分の文書が読めることと他人の文書が読めないこと |
| ホスト監査 | 権限・秘密情報・設定とバックアップを確認する | 最小権限に直しても必要な機能を残せたか |
| 調査 | 原本を保全し、時刻とイベントを関連付ける | 観測事実、推測、未確認の範囲を分けられるか |
| 報告 | 対象、再現可能な証拠、影響、修正と再確認を伝える | 別の担当者が根拠を確認し、対応を判断できるか |

|---|---|
| Docker デーモンが使える | 本物の Docker でコンテナを起動・検証（`lq-` で始まる名前・`lq=1` ラベルのコンテナだけを操作します） |
| 未インストール / 権限なし | **シミュレーションモード**：学習用の模擬 `docker` コマンドが自動で使われます。`run / ps / logs / exec -it / inspect / build / images / rm / prune / compose / network` などを本物と同じ書式・出力・エラーメッセージで再現。Dockerfile の構文エラーやレイヤーキャッシュ（CACHED 表示）、compose.yaml の検証、ポート衝突や名前衝突、ユーザー定義ネットワークと名前解決、マルチステージビルド、ヘルスチェックと再起動ポリシーもシミュレートします |

メニューの「設定」で `auto` / `mock`（常にシミュレーション）/ `real` を切り替えられます。
自分の Docker 環境を汚したくない場合は `mock` がおすすめです。

## 📴 オフラインでの利用

**はじめて・基礎練習モードはオフラインで学べます。実践モードも、必要なLinuxコマンドを用意すれば全102ミッションを遊べます。**
必要な Linux コマンドを事前に導入しておけば、追加のダウンロードや `pip install` は不要です。ゲーム本体は Python 3 標準ライブラリと bash で動作し、Docker は必須ではありません。

### なぜオフラインで動くのか

| 要素 | オフライン時の動作 |
|---|---|
| ゲーム本体・判定エンジン | Python 3 標準ライブラリのみ。外部ライブラリ・外部 API への通信は一切ありません |
| Stage 1〜3 | ローカルのファイル・プロセス・環境変数だけを扱うので影響なし |
| Stage 4 の HTTP / ポート / `curl` 問題 | 練習用サーバーを **`127.0.0.1`（自分自身）** に立てて使うため、ネットが無くても動きます |
| Stage 4 の `ping` | 宛先は `127.0.0.1`（ループバック）なのでオフラインでも応答します |
| Stage 4 の `dig`（4-6） | 下記「4-6 の注意」を参照。オフラインでもクリアできるよう判定を調整済み |
| Stage 4 の `ssh` / `rsync` / `tar` / `zip` | すべてローカル内で完結（`ssh -G` で設定を解析するだけで、実際の接続はしません） |
| Stage 5・7（Docker） | **シミュレーションモードなら完全オフライン**で動作します（模擬 `docker` コマンドはイメージのダウンロードを行いません） |
| Stage 6・Stage 7 の管理課題 | ローカルのファイルと模擬 `crontab`・管理コマンドだけで動作します（`jq`・`vim` などは事前に導入） |
| 進捗の保存 | ローカルの `save_data.json` に書き込むだけ |

### 4-6（ping / dig）の注意

`dig nonexistent-penguin.invalid` は DNS サーバーへの問い合わせです。オフライン時の結果は環境によって変わります。

- **systemd-resolved が動いている一般的な Ubuntu**：`.invalid` はローカルで処理されるため、オフラインでも通常どおり `status: NXDOMAIN` が表示されます。
- **DNS サーバーに届かない環境**：`;; connection timed out; no servers could be reached` と表示され、status 行が出ません。
  この場合でも、「`.invalid` は存在しないドメイン → 正常なら `NXDOMAIN`」という知識で `submit NXDOMAIN` すればクリアできます（`check` 時にも案内が表示されます）。
- DNS サーバーが `SERVFAIL` を返す環境では、その PC で `dig` が実際に返したステータスも正解として扱います。

### Docker を本物で使う場合（`real` モード）のみ注意

本物の Docker で Stage 5・7 を遊ぶ場合、`nginx` / `alpine` / `python:3.12-slim` / `golang:1.23` など、課題が指定するイメージが必要です。Stage 7 の Go アプリはビルド用コンテナ内でコンパイルするため、ホストへの Go のインストールは不要です。
手元にイメージが無い状態でオフラインになると `docker run` がイメージを取得できず失敗します。

- オフラインで遊ぶ予定なら、**メニュー →「設定」で Docker モードを `mock` にする**のが確実です（`auto` でも Docker が無ければ自動で `mock` になります）。
- オンラインのうちに 課題で使うイメージをすべて取得しておく必要があります。例: `for image in nginx alpine python:3.12-slim golang:1.23; do docker pull "$image"; done`。課題内で生成するイメージも、必要なら事前にビルドしてください。

### 実践モードで使うコマンドを事前に準備する

オフラインになると `apt install` ができないので、事前に `./start.sh --check` で不足コマンドを確認してください。
不足がある場合はオンラインのうちに以下を実行しておきます。これは教材の外で行う実際のインストールです。`sudo`・`apt`をまだ知らない人は、先にはじめてモードで意味を確認してください。

```bash
sudo apt install curl iputils-ping dnsutils rsync zip unzip lsof openssh-client procps iproute2 jq vim
```

`--check` の結果がすべて ✔ なら、あとはネットワークを切っても問題ありません。

### 判定の仕組み（runner.py）
サブシェルの `PROMPT_COMMAND` が、コマンドを実行するたびに **カレントディレクトリ・環境変数・ジョブ一覧・終了コード・履歴** を `workspace/.lq_state/` に記録します。

「何が足りないか」を具体的な日本語でフィードバックします（例:「標準エラー出力が入っていません。`2>&1` を使いましょう」）。

## ⚠ 注意事項

- はじめて・基礎練習モードの `sudo`・`apt`・SSH・転送は模擬操作です。実際のOSの管理者権限取得、ソフトの追加・削除、外部サーバーへの接続は行いません。
- **実践モード**のサブシェルは **本物の bash** です。作業は `workspace/` の中で行ってください（外に出るとプロンプトに赤字で警告が出ます）。
  `rm -rf` などは実際に効くので、サンドボックスの外では慎重に！
- ミッション用のバックグラウンドプロセス（暴走プロセス役・HTTPサーバー役）は、ミッション終了時に自動で停止されます。
- Stage 4 のサーバーはすべて `127.0.0.1` のみで待ち受け、外部には公開されません。`ping` / `dig` も自分自身（ループバック）とローカルの DNS リゾルバにしか問い合わせません。
- 4-7 の SSH 設定は作業ディレクトリ内の `.ssh/` で練習するため、本物の `~/.ssh` は変更しません。
- 予期せぬエラーが起きた場合は `workspace/error.log` に詳細が記録され、メニューに戻ります。

## 🛠 トラブルシューティング

| 症状 | 対処 |
|---|---|
| 文字化けする | 端末の文字コードを UTF-8 に。`echo $LANG` が `ja_JP.UTF-8` か `C.UTF-8` であること |
| 罫線がずれる | 端末の「曖昧な幅の文字」を「半角」に設定してください |
| 色が付かない / 消したい | `NO_COLOR=1 ./start.sh` で色なし表示 |
| `dig` や `lsof` が無い | `sudo apt install dnsutils lsof`（`./start.sh --check` で確認） |
| 進捗をリセットしたい | メニュー →「設定」→ `[r]`、または `save_data.json` を削除 |
